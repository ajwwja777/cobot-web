# 单 terminal：准备 → 录制（含手动归位）→ 自动归位 → 播放 → 重播/下一条

2026-09-01 后臂物理按钮示教版。**输入 `start` 后托稳后双臂，只对 terminal 点名的后臂各短按一次按钮；已经处于示教状态的一侧不要再按。程序确认两侧进入重力补偿拖动示教后才继续。** 录制、归位、播放、重播和下一条全部在 terminal 操作；不启动旧 Task2 按钮协调器。

后面两只机械臂作为手动输入，控制前左右工作臂。**中臂启动后先慢速抬到 PI05 预备姿态，确认到位后始终保持。** 只保存关节动作和反馈，不启动 AVP、模型、相机，不上传数据。

## 启动（cobot 的同一个 Bash terminal）

```bash
cd /home/agilex/cobot_magic/aloha-devel/Piper-AVP-Teleop

# 可选：仅预览参数，不配置 CAN、不启动 ROS、不发动作
bash multi_arm_launch_tools/rear_record_replay.sh

# 运行；后面的录放操作都在这个 terminal 完成
bash multi_arm_launch_tools/rear_record_replay.sh --execute
```

Mac 可先 `ssh -t cobot_magic`。先在原终端退出旧三/五臂 launch、rollout、AVP、固定中臂控制器和其他机器人控制器。检测到冲突时本工具会拒绝启动，不会杀其他会话。只启动相机的旧终端可保留。

第一次配置 CAN 可能要求输入 sudo 密码。配置沿用 `can_config_cobot.sh task2`；如果已配置好五条机械臂 CAN，可以加 `--skip-can`。

**输入 `start` 确认启动前：**

- 后双臂必须分别连接 `can_rear_left/right`，并已上电、能提供关节反馈。不能直接套在旧共用 CAN 的主从接法上，不会自动切固件主从角色。
- **输入 `start` 前托住后双臂及其夹爪。** terminal 提示后，分别给左右后臂按钮短按一次并立即松开。按钮是切换式，不要长按；进入时可能下沉。
- 灯亮只能作为现场参考，不能作为程序放行条件。正确反馈必须为 `ctrl=0x02 / teach=0x01 / motors=111111`，两侧连续至少 0.3 秒；terminal 会分别打印“按钮示教已检测”和“拖动示教状态已确认”。
- 一侧确认后不要再按该侧；等另一侧也确认。录制、归位、播放、重播和下一条期间都不要再按按钮。
- 程序不会发送后臂使能、失能、示教、关节、夹爪或主从角色命令。如果检测到 `ctrl=0x01` CAN 控制，先退出其他后臂控制器再重启本流程。
- 前左右臂与中臂会使能；现有驱动启动时会闭合夹爪，夹爪内不得有人手或需保留物品。
- **前臂不能处于按钮示教。** 程序启动驱动后先发送实测当前位置作为保持目标，并要求前左、前右和中臂均为 `ctrl=0x01 / teach=0x00`。若 terminal 单独提示“前左臂/前右臂仍在按钮示教”，托稳提示的**前臂**并短按一次它自己的按钮退出；此时不要再按后臂按钮。
- 模式确认后，程序会让前左、前右臂的腕关节各往返 `0.012 rad`（约 0.69°）。两侧实测反馈都跟随后才继续；任一侧不动会在录制前退出。自检时不要触碰机械臂。
- **清空中臂抬升路径。** 输入 `start` 后，中臂会从实测姿态慢速移动到部署预备姿态；前左右臂保持。本流程不调用全三臂复位，也不执行 PI05 复位脚本中的夹爪开合步骤（底层驱动启动时的闭合仍存在）。
- 工作区无人，急停可及。软件关节限幅与慢速归位不等于碰撞保护。

## 一条录制与回放

所有键均为“输入字符后按回车”。

后双臂按钮示教确认后，程序才会启动前/中臂驱动。前三臂 CAN 模式确认、前双臂微动跟随自检通过并回到原位后，程序才抬中臂。随后等待“**中臂已抬起到位**”。中臂目标来自 `PI05/deploy/pi05_ramp_to_initial.py` 的 `READY_JOINT_TARGETS["mid"]`：

```text
六关节 rad: [0.0463, 0.5300, -0.5562, 0.0000, 0.6500, 0.0000]
夹爪 m:     0.0
```

默认关节目标速度上限 0.20 rad/s（`--ramp-speed`），夹爪 0.02 m/s。指令到达目标且实测六关节误差小于 0.03 rad、夹爪误差小于 0.01 m，连续 5 个 tick 后才开放录放；60 秒未到位则退出。中臂抬升不录入动作文件，后续固定目标也不会随 `n`、归位或重播重新捕获。

抬升中可按回车或 `s` 中止并保持最后目标；此时不能绕过初始化录放，需要 `q` 退出，排查后重新启动。正常启动到位不需要额外按键。

| 步骤 | terminal / 人的操作 | 机器人行为 |
|---|---|---|
| 1 | 输入 `start` 后托稳后臂，左右后臂按钮各短按一次；若另有提示，只对点名的前臂短按一次退出示教 | 后臂进入拖动示教；前三臂进入 CAN 模式；前双臂微动自检并回原位；中臂到预备姿态 |
| 2 | 输入 `r` | 捕获当前前后臂参考姿态，开始跟随并录制 |
| 3 | 完成任务，然后你自己把后臂/动作归位 | **继续录制**，前左右臂继续跟随 |
| 4 | 确认人已离开前臂返回路径、路径无障碍，按回车或输入 `e` | 停录保存，断开后臂跟随；前左右臂自动慢速归位到录制第一帧 |
| 5 | 等程序提示“已归位，等待播放” | 前左右臂停在起点；不会自行开始播放 |
| 6 | 恢复物体初态、人员离开，输入 `p` | 播放录制动作，包含所选卡顿 |
| 7 | 播放结束后选择 `a` / `n` / `q` | 重播 / 下一次录制 / 退出 |

**你在停录前手动归位的那一段也会被录下来，并在回放时执行；程序不裁剪这段。**

“初始位置”定义为**本条录制的第一帧前双臂关节目标**，不是额外的模型预设零位。第一帧先保持当前目标，后续才跟随后臂变化，以免按 `r` 时跳变。前后臂采用 `前臂参考 + 后臂当前 - 后臂参考` 的关节增量映射，不要求两组臂一开始角度完全相同。

夹爪也使用增量映射。开录前应让后臂夹爪开合量与前臂接近（前臂驱动启动后通常是闭合状态），否则可能限制可用的夹爪开合范围；先用无负载短轨迹确认。

程序不向后臂夹爪发送控制命令。正式录制前，需现场确认两只夹爪能手动开合且反馈正常。

夹住物体或编码器零点偏差可能使后臂夹爪实测值略低于 0 或高于标称 0.08 m；这不是流程故障。有限数值会裁剪到 `0..0.08 m` 后参与增量映射，不会因此停录。只有 NaN/Inf 才按反馈瞬断处理并使用恢复宽限。

如果需要先通过后臂调整前臂姿态，再决定何时开录，可在准备状态输入可选的 `t`：只跟随、不录制；准备好再输入 `r`。正常流程直接 `r` 即可，不强制 `t`。

## 播放结束的选择

- **`a` 再播放一次**：先慢速归位到同一条录制第一帧，反馈到位后自动播放。输入前就应恢复好场景并清空返回路径；不会再要求第二次 `p`。
- **`n` 下一次录制**：进入准备状态，前臂保持，不跟随后臂。你重新摆好后臂，输入 `r` 即开始下一条。每条重新捕获前后臂参考姿态，不沿用上一条偏移；旧数据保留，不覆盖。
- **`q` 退出**：清理本流程启动的驱动和 CAN 连接；不自动回零，也不退出后臂示教。先放稳后臂；需要退出示教时，流程结束后给左右按钮各再短按一次。
- 如果想重播前先归位、再慢慢整理场景，可用 **`p` 归位 → 到位后 `p` 播放**，而不是 `a`。

## 中止与归位的区别

- **录制中，回车/`e` = 正常结束，并立即开始前双臂慢速归位。** 这就是指定的主流程；不要在返回路径仍有人时按。
- **任意阶段，`s` = 中止并保持最后目标，不自动归位或播放。** 录制中 `s` 会保存中断文件，不允许直接回放。
- 回放、归位、跟随预览中，裸回车也用于中止；在 `a` 的归位途中中止，会取消后续自动播放。
- 启动抬升中，回车/`s` 中止中臂，不开放后续录放；到位后中臂始终保持预备姿态，不随录放中止而回零。
- 录制默认最多 600 秒，可用 `--max-seconds` 调整；达到上限会保存并保持，**不会自动归位**，因为你可能尚未手动归位。准备好后输入 `p` 归位。
- `Ctrl+C`、终端断开、反馈过期、驱动异常等会尝试保存中断文件并退出，不自动归位。

停止更新目标不等于物理急停；机械臂可能继续向最后目标收敛，后臂仍可能下垂。危险时用现场硬急停，不依赖软件按键。

## 回放的小卡顿

默认 **30 Hz，每执行 30 帧，在下一帧之前额外保持约 0.28 秒**：

- `--dwell-s 0.10`：来自你指定的部署 `USE.md` 中的 chunk boundary dwell。
- `--infer-s 0.18`：参考 2026-08-29 historyREPEAT 评估日志中约 0.17–0.18 秒的平均同步推理耗时；不是当前模型负载的实时测量。

```bash
# 默认卡顿
bash multi_arm_launch_tools/rear_record_replay.sh --execute \
  --chunk 30 --dwell-s 0.10 --infer-s 0.18

# 只加 100ms 卡顿
bash multi_arm_launch_tools/rear_record_replay.sh --execute --infer-s 0

# 卡顿加入可复现的 ±30ms 波动
bash multi_arm_launch_tools/rear_record_replay.sh --execute \
  --jitter-s 0.03 --seed 42

# 无边界卡顿对照
bash multi_arm_launch_tools/rear_record_replay.sh --execute \
  --dwell-s 0 --infer-s 0 --jitter-s 0
```

停顿时重复发布上一目标，夹爪和中臂也保持；不跳帧，不在停顿后追赶。普通帧间隔也保留，因此默认边界相邻新目标间隔约为 `1/30 + 0.28` 秒，并可能因控制 tick 量化多约 33ms。不是硬实时系统。

只模拟动作时序，不模拟模型预测误差、EEF/IK/EMA 或冷启动。真实同步推理可能完全停止发包；本工具重复保持目标，驱动 watchdog 的表现可能不同。保持目标不代表已经测得零速度。

手动跟随默认每 tick 限制关节目标变化 0.05 rad、夹爪变化 0.005 m；录制的是限幅后实际发布的目标。归位默认 0.20 rad/s、夹爪 0.02 m/s，并检查反馈是否到位；没有碰撞路径规划。中臂只在启动时抬升，之后不参与前双臂归位。

## 文件、只回放与验证

默认保存到 `Piper-AVP-Teleop/data/rear_record_replay/日期时间/`，程序会打印完整路径。目录内有 `arms.log`、`supervisor.log`、`settings.json`、`episode_时间.hdf5`。`arms.log` 是前三臂 roslaunch 日志；`supervisor.log` 会持久化主流程异常和完整调用栈。可用 `--output-dir` 指定目录。

HDF5 格式保持不变：`action[T,14]`、`observations/qpos[T,14]`、`observations/qpos_mid[T,7]`、`mid_hold[7]`、`timestamps/monotonic_s[T]`。14 维为左臂 6 关节 + 左夹爪，再右臂 6 关节 + 右夹爪。不是原三臂/图像训练数据，不要交给旧 `play_data.py`。

将 `EP` 设置为程序打印的真实文件路径后：

```bash
# 离线校验，不初始化 ROS
bash multi_arm_launch_tools/rear_record_replay.sh --inspect "$EP"

# 仅回放已有文件：p 归位 → p 播放，或 a 归位后自动播放
bash multi_arm_launch_tools/rear_record_replay.sh --execute --skip-can --episode "$EP"
```

仅回放会话同样先初始化中臂，但不改变后臂模式，也不允许切到新录制；要录新数据，请退出后不带 `--episode` 重新启动。正常未带 `--episode` 的会话支持连续录制与重播。若旧文件录制时的中臂位置与当前固定预备姿态相差超过 0.05 rad，会拒绝回放，需在新的固定姿态重新录制。

专用 launch 只启动前左、前右、中臂的 3 个现有 `piper_start_ms_node.py`，均为 `mode=1, auto_enable=true`。主程序通过 `data_collect/rear_teach_input.py` 独占后两条 CAN 的 SDK 连接，只读取按钮示教状态和关节反馈；不再同时启动后臂 stock 驱动。不要单独运行 launch 来代替入口脚本。

后臂 SDK 连接在整个流程中只读。**不调用后臂 `MotionCtrl_1`、`EnableArm`、`DisableArm`、复位、`MotionCtrl_2`、`JointCtrl`、`GripperCtrl` 或主从角色切换接口。** 后续准备、录制、归位、播放和下一条均要求后臂持续保持 `ctrl=0x02 / teach=0x01 / motors=111111`。再次按任一按钮导致该侧退出示教时，流程立即停止跟随。

当前后臂固件 `S-V1.7-3` 上，真机确认的轻便路径就是物理按钮；软件请求示教分别试过电机失能和使能两种前置状态，都没有进入可确认的拖动状态。本版本因此完全依赖按钮反馈，不再尝试软件切换。

运行中如果后臂 SDK 的某类反馈单次超过 250 ms 未更新，程序会打印 `[WARN]`，并保持最后的后臂输入和前臂目标；默认给 1 秒恢复宽限（`--rear-feedback-grace`）。反馈恢复后继续运行。连续中断超过宽限才退出；电机保护、后臂退出示教或电机失能、前三臂异常和前臂跟踪偏差仍立即退出，不使用宽限掩盖。

前三臂的 `ctrl_mode`、`teach_status`、`arm_status` 和 `err_code` 会持续参与安全检查。前臂处于 `ctrl=0x02 / teach=0x01` 时，ROS 节点和 CAN 链路仍可能显示正常，但机械臂不会执行关节目标；本工具不再把这种状态误判为可录制。接管提示、自检结果和失败时的完整状态写入 `supervisor.log`。等待前臂退出示教默认最多 60 秒，可用 `--front-control-timeout` 调整；微动幅度可用 `--front-self-test-rad` 调整，不建议现场放大。

**验证边界：只有离线模拟、语法和 launch 解析验证，没有实际执行真机动作。** 正式使用前，应在现场以短行程、无负载轨迹确认后臂可手动拖动、反馈有效、方向和夹爪映射正确。

```bash
python -m unittest discover -s tests -p test_rear_record_replay.py -v
bash -n multi_arm_launch_tools/rear_record_replay.sh
roslaunch --nodes multi_arm_launch_tools/launch/start_rear_record_replay.launch
```
