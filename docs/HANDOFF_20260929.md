## 明日现场顺序

先确认机械臂周围安全，再由操作者启动硬件。不要在模型运行或录制中执行重启网页。

```bash
cd /home/agilex/jiaan/project/cobot-control
python3 scripts/control.py status
# 按现场需要手动执行：
./scripts/can_up.sh
python3 scripts/control.py start roscore
python3 scripts/control.py start arms
python3 scripts/control.py start cameras

cd /home/agilex/jiaan/project/cobot-web
./scripts/ui_status.sh
.venv/bin/python scripts/models.py list
.venv/bin/python scripts/models.py check plug-v3-warmup-5k

cd /home/agilex/jiaan/project/rl-platform
envs/online/bin/python scripts/preflight.py
./scripts/rlt_status.sh
```

1. 在操作台确认CAN/ROS、相机、各臂和夹爪状态；黄灯查看具体原因，再处理使能或示教条件。
2. 在数据采集选择test目录，无模型先验收开始、空格暂停/继续、节点、暂停后→保存、←放弃和所选复位。放弃后目录和记录都不应新增该Episode。
3. 手动选择并加载模型，等明确就绪；采集和部署共享已加载模型。先验证冻结warmup的短轮次与结果保存，再验证HIL。
4. RLT在线选择对应online入口；启用成功/失败后使用↑/↓。按原在线流程收集有效轮次，观察Replay新增和Learner/Actor版本，不把“模型已加载”当作“在线已更新”。
5. 结束Session、释放模型，再按相机→机械臂→ROS顺序停止。不启动第二套手工rlt_up与网页模型。

完整按钮、底层脚本和HTTP命令见[COMMAND_LINE](COMMAND_LINE.md)；HTTP503、超时、磁盘与进程恢复见[WEB_RECOVERY](WEB_RECOVERY.md)。发生HTTP结果不确定时先读Session/录制状态，避免重复提交成功/失败。刷新只恢复连接，不能修复ROS、USB或磁盘故障。
